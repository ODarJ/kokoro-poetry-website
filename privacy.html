Privacy Policy

Kokoro Poetry Video · Last updated: October 10, 2026

1. What this project is

Kokoro Poetry Video is an open-source automation that produces narrated English poetry videos and may publish them to accounts owned and controlled by the project operator. It runs on GitHub Actions. It is not a public-facing service: it has no user accounts, no sign-up, and no website that collects personal information from visitors.

Source code for the pipeline: github.com/ODarJ/kokoro-poetry-video-

This website is a static informational site for the project.

2. Information the project processes

The project processes the following categories of information in order to generate and (when enabled) publish videos:

  • Poem titles, authors, and text (from a prepared list of poems intended to be public domain or otherwise lawfully usable).
  • AI-generated planning data for each video (narration text, mood, voice selection, background scene plan, music search keywords, titles, and descriptions).
  • Downloaded media used as backgrounds (from Pexels) and background music (from Freesound, limited to Creative Commons 0).
  • Generated audio (Kokoro text-to-speech), video files, and synchronized subtitles.
  • Pipeline state (which poems have been processed, upload results, and platform-returned identifiers or links).
  • OAuth or equivalent credentials needed to publish to the operator’s own accounts on enabled platforms.

The project does not collect personal information from members of the public, website visitors, or end viewers of the published videos.

3. OAuth tokens and account authorization

When publishing is enabled for a platform, the project uses that platform’s official API. The account owner authorizes the project once. The resulting tokens (for example, refresh tokens or access tokens) are used solely to perform the actions the owner has authorized—primarily uploading a video and its metadata to the owner’s own account or page.

  • YouTube (Google): requests only the YouTube upload scope. Use of information received from Google APIs adheres to the Google API Services User Data Policy, including the Limited Use requirements. Google user data is not sold, not used for advertising, and not used to build profiles. It is not shared with third parties except as required to complete the authorized upload.
  • TikTok: uses the TikTok Content Posting API. The project posts only to the authorizing owner’s account. The exact capabilities available depend on the app’s approval status with TikTok. Tokens are used only for the authorized posting actions.
  • Facebook / Meta: when enabled, posts to a Facebook Page controlled by the owner via the Meta Graph API.

Tokens and API keys are stored exclusively as GitHub Actions Secrets. They are injected as environment variables only while a workflow runs. They are not written into source code, generated files, pipeline state, or unmasked logs.

4. Video uploads

When a platform is enabled, the generated video file and its title, description (and any other metadata required by that platform’s API) are sent to the platform’s official API for posting to the authorizing owner’s account. The project records the API response (success or failure and any identifiers returned) in the pipeline state so that results can be audited by the owner.

Default privacy settings on platforms that support them are set to private or restricted until the owner changes them. Visibility and retention of uploaded videos are governed by the respective platform and by the owner’s account settings.

5. Third-party services

The project interacts with the following categories of third-party services:

  • AI providers (for example, services used for planning prompts): receive the poem title/author and a planning prompt. One request is made per poem. Credentials and OAuth tokens for publishing platforms are not sent to these providers.
  • Pexels: receives search keywords and returns photos or videos used as backgrounds.
  • Freesound: receives search keywords and returns Creative Commons 0 music used as background audio.
  • Platform APIs (YouTube / Google, TikTok Content Posting API, Meta Graph API when enabled): receive the video and metadata for the authorized upload.
  • GitHub: hosts the code, runs the workflows, and stores secrets, state, and temporary artifacts.

Each of these services processes data under its own privacy policy and terms. The project does not control those policies.

7. Security

  • Credentials are stored only in GitHub Actions Secrets and are never committed to the repository.
  • Only the minimum permissions required for the intended upload actions are requested.
  • Workflows are designed so that only one pipeline run updates shared state at a time.
  • Videos are uploaded with restrictive privacy settings by default where the platform allows it.

No system is perfectly secure. The owner is responsible for reviewing access, rotating credentials when appropriate, and monitoring the accounts used for publishing.

8. Visitors to this website

This website is static HTML. It does not set cookies for tracking, does not use analytics or advertising scripts, and does not contain forms that collect personal information. GitHub Pages (the host) may process technical data such as IP addresses under GitHub’s privacy statement.

9. Children

The project is not directed at children and does not knowingly collect personal information from anyone, including children.

10. Revoking access and deleting data

  • Google / YouTube: revoke access at myaccount.google.com/permissions and delete the corresponding GitHub Actions Secrets.
  • TikTok: remove the app from the connected apps / authorized apps section of the TikTok account and delete the corresponding GitHub Actions Secrets.
  • Facebook / Meta: remove the app from the connected apps settings of the relevant account or Page and delete the corresponding secrets.
  • Project data: delete the state files, Actions artifacts, or the entire repository as desired.
  • Uploaded videos: delete them directly on each platform.
